> **상위 플랜**: [`feat_v0_5_0_plan.md`](../feat_v0_5_0_plan.md)

> 전체 브라우저 e2e (S1~S7 풀세트) / README · dev log · 사용자 문서 polish 는 **Phase 9-2** 에서 본다.
> **Branch**: `feature/#<issue>-llm-router`
> **Base**: `develop`
> **회귀 보호 핵심 계약 3 가지**:
> 1. DATE_CONDITION_KEYWORDS 는 LLM 보다 먼저 평가되어 calendar 도구 라우팅을 끊지 않는다 (v0.4.2 / #73 보호).

## 1. 목적 (Why)

키워드 라우터의 대명사/메타-요청/가설 질문 한계를 해소하기 위해, **route 결정만** LLM 에 위임하고
`workflow_key` 는 DB RouterRule 전담을 유지한다. Phase 9-1 은 본체 인프라 (LLM 호출/토큰 기록/라우터 시그니처/순환 import 차단)
+ focused regression + 최소 수동 smoke 까지를 PR 1 개로 닫는다.
전체 브라우저 e2e (S1~S7 풀세트) / README · dev log · 사용자 문서 polish 는 **Phase 9-2** 에서 본다.

### 단계 5 — `chat/services/llm_router.py` 신규
> **핵심 계약 (순환 import 차단 — 강화)**: `chat/services/llm_router.py` 안에는 literal `RouteDecision` 문자열이 어떤 형태로도 등장하지 않는다 — import 금지뿐 아니라 주석/docstring/문자열 리터럴/타입 힌트 어디에서도 금지. 자체 `LlmRouteResult` (neutral dataclass) 만 반환한다. DoD 의 `grep -n RouteDecision chat/services/llm_router.py` 빈 결과로 검증.

1. **Imports (계약 명시)**
   - `from chat.graph.routes import ALL_ROUTES`
   - `from chat.services.prompt_loader import load_prompt`
   - **`from chat.services.single_shot.llm import run_chat_completion`** (필수)
   - **`from chat.services.single_shot.postprocess import record_token_usage`** (필수)
   - `from chat.services.token_purpose import PURPOSE_LLM_ROUTER`
   - `chat.services.question_router` 의 라우팅 결정 타입은 **import 금지**. literal `RouteDecision` 문자열도 어떤 형태로도 쓰지 않는다. 모듈 최상단 docstring 에는 우회 표현으로만 명시 — 예: `"question_router 의 타입은 본 모듈에서 import 하지 않는다 — 순환 차단"`. DoD `grep -n RouteDecision chat/services/llm_router.py` 빈 결과 유지가 검증선.
2. **`LlmRouteResult` dataclass (frozen)**
   - 필드 정확히 2 개: `route: str`, `reason: str`.
   - `workflow_key` 필드 **없음** — LLM 의 workflow_key hallucination 을 타입 수준에서 자연 드롭.
3. **History helper 계약 (query_rewriter 와 동일 스타일)**
   - 모듈 상단 상수: `_ROUTER_HISTORY_TURNS = 3` (user/assistant 합산 메시지 개수 기준).
   - `_tail_history(history, max_messages)` —
     - `role in ('user', 'assistant')` + `content` 가 비어있지 않은 메시지만 필터.
     - 필터 후 `trimmed[-max_messages:]` 로 tail 슬라이스.
     - 빈 history / 전부 system 메시지 / content 없는 메시지만 들어와도 안전하게 `[]` 반환.
   - `_format_user_payload(question, history_slice)` — `query_rewriter._format_user_payload` 와 동일한 라인 포맷:
     ```
     Conversation:
     {role}: {content.strip()}
     ... (반복)
     <빈 줄>
     Current question: {question.strip()}
     Route:
     ```
     마지막 `Rewrite:` 가 아닌 **`Route:`** 로 끝낸다 (LLM 이 라우터 출력으로 전환되도록 신호).
4. **`_llm_classify(question, history)`**
   - 시스템 프롬프트: `load_prompt('chat/llm_router.md')`.
   - 사용자 페이로드: `_format_user_payload(question, _tail_history(history, _ROUTER_HISTORY_TURNS))`.
     - `history` 가 `None` 인 분기는 호출자 (`route_question`) 가 `history or []` 디폴트로 차단 — 본 함수는 list 라고 가정.
   - `run_chat_completion(messages, model=os.environ.get('OPENAI_AUX_MODEL') or os.environ.get('OPENAI_MODEL'))` 호출.
   - **`record_token_usage(model, usage, purpose=PURPOSE_LLM_ROUTER)`** 정확히 1 회 호출.
   - 반환값은 `_parse_and_validate(text)` 결과 (`Optional[LlmRouteResult]`).
5. **`_parse_and_validate(text)` — LLM 출력 검증 계약**
   | 단계 | 통과 조건 | 위반 시 |
   |---|---|---|
   | 1. JSON 파싱 | `json.loads(text)` 성공 | `None` 반환 → keyword fallback |
   | 2. 객체 형태 | `isinstance(parsed, dict)` | `None` 반환 → keyword fallback |
   | 3. route 멤버십 | `parsed['route'] in ALL_ROUTES` | `None` 반환 → keyword fallback |
   | 4. reason 정제 | `str.strip()`, 길이 ≤ 120 (초과 시 절단) | 통과 (정제만) |
   | 5. workflow_key | 출력에 있어도 **무시** (`LlmRouteResult` 가 필드를 안 가짐) | 통과 (자연 드롭) |
   - 1~3 어디서 실패하든 `None` 반환 → 호출자 (`route_question`) 가 Tier 4 키워드 fallback 으로 진행.
6. **로깅**: 예외는 `logger.warning('LLM 라우터 실패, 키워드 fallback: %s', exc)` 로만. PII/질문 본문 직접 로그 금지.

### 단계 6 — `route_question()` 시그니처 확장 + 4-tier 통합
1. `chat/services/question_router.py`
   - **typing import 확장**: 현재 `chat/services/question_router.py:36` 는 `from typing import List, Optional` 만 있고 `from __future__ import annotations` 가 없음.
     `from typing import Dict, List, Optional` 로 `Dict` 추가 (기존 스타일 유지, 한 줄 변경).
     - `list[dict] | None` PEP-604 표기는 일관성 깨므로 채택 안 함.
   - `def route_question(question: str, history: Optional[List[Dict]] = None) -> RouteDecision:` 로 시그니처 확장.
   - `history = history or []` 첫 줄 디폴트.
   - **4-tier 평가 순서 (엄수)**:
     - **Tier 1**: DB RouterRule (`_match_db_rules`) — 매치 시 즉시 반환, LLM 호출 0.
     - **Tier 2**: `DATE_CONDITION_KEYWORDS` 매치 시 `RouteDecision(route=ROUTE_AGENT, reason='date_condition_keyword', matched_rules=hits)` 즉시 반환. **LLM 호출 0.**
     - **Tier 3**: `_llm_classify(question, history)` 호출 (예외는 catch 후 None). `LlmRouteResult` → `RouteDecision` 변환 시 **`workflow_key=''` 강제**.
     - **Tier 4**: 기존 inline 키워드 fallback (WORKFLOW / AGENT / default). **helper 추출 금지** — DATE_CONDITION 블록만 LLM 호출 위로 이동시키는 최소 변경.
2. **`LlmRouteResult` → `RouteDecision` 변환 계약**
   ```python
   if llm_result is not None:
       return RouteDecision(
           route=llm_result.route,
           reason=llm_result.reason,
           workflow_key='',  # DB RouterRule 전담 — LLM 출력은 항상 무시
       )
   ```
   - `workflow_key=''` 는 `workflow_node` 의 single_shot 자동 폴백 (`workflow.py:44-49`) 과 결합되어 회귀 0 보장.
3. **import**: `from chat.services.llm_router import LlmRouteResult, _llm_classify` — `question_router` 쪽에서만 import (단방향).
