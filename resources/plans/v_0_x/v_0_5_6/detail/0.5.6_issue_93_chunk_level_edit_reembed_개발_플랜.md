## 1. 현재 구조 요약

### 1.1 모델 (`files/models.py`)

- `Document`
  - `status`: `pending / reviewing / processing / ready / failed`
  - `edited_text`: 검토 단계에서 사용자가 편집한 원문. **현재는 임베딩 소스의 단일 진실(SoT)**.
  - `error_message`: 마지막 실패 메시지.
- `DocumentChunk`
  - `(document, chunk_index)` UniqueConstraint.
  - `content` (TextField), `embedding` (1536-dim VectorField), `metadata` (JSON).
  - HNSW vector index 보유 — content/embedding은 BO 편집만으로 즉시 검색에 반영됨.

### 1.2 파이프라인 (`files/services/pipeline.py`)

- `extract_document(doc)`: 파일 → `edited_text` (REVIEWING)
- `finalize_document(doc)`: `edited_text` → chunking+embed → bulk_create (READY).
- `reembed_document(doc, new_text)`: READY 문서 재임베딩. 실패 시 기존 chunks/edited_text/status 보존 + error_message 갱신 — 동일 안전 계약을 chunk 단위에도 차용.

### 1.3 임베딩 (`files/services/embedder.py`)

- `embed_text(text) -> List[float]`. `EmbeddingError` 정의.

### 1.4 BO 흐름 (`bo/views/files.py`, 템플릿)

- `files.html`: 문서 목록. `청크 확인` 버튼 → `bo:chunks`.
- `files_chunks.html`: chunk_index 순으로 read-only `<pre>` 표시. 현재 수정 진입점 없음.
- `files_review.html` + `confirm` view: 문서 전체 `edited_text` 편집 → `reembed_document` 호출.
- `bo:urls.py`: `files/<pk>/chunks/` 정의됨.
- **인증/권한**: 현재 BO 파일 관련 view들은 명시적 staff/login 데코레이터를 두지 않는다. 본 신규 라우트도 **기존 BO 라우팅 패턴을 그대로 따른다**. 전역 BO 인증 변경은 본 이슈 범위 밖.

### 1.5 검색 측 영향 (`chat/services/single_shot/retrieval.py`)

- 검색은 `DocumentChunk.content` / `embedding` / `chunk_index` 만 사용. `Document.edited_text` 미참조.
- → chunk content/embedding 만 갱신하면 검색 결과는 즉시 반영. 별도 캐시 무효화 불필요.

## 3. Chunk 수정 View / URL / Template UX 설계

### 3.1 URL

```
GET  /bo/files/<int:pk>/chunks/<int:chunk_pk>/edit/    name='chunk_edit'
POST /bo/files/<int:pk>/chunks/<int:chunk_pk>/edit/    name='chunk_edit'
```

- View 안에서 안전 조회:
  ```python
  chunk = get_object_or_404(
      DocumentChunk.objects.select_related('document'),
      pk=chunk_pk,
      document_id=pk,
  )
  ```
  → 다른 문서 소속 chunk_pk 는 자동 404.
- 상태 분기는 `chunk.document.status` 기준. `chunk.document.status != Document.Status.READY` 면 `messages.error` 후 `bo:chunks` redirect.

### 3.2 `files_chunks.html` 수정

- 각 chunk 카드 우측에 `수정` 버튼.
  - **`document.status == 'ready'` 일 때만 노출** (그 외 상태에서는 버튼 자체 미렌더).
- 페이지 상단 안내 박스:
  > "한 chunk 의 텍스트만 수정합니다. 해당 chunk만 재임베딩되며, 다른 chunk 와 문서 본문(`edited_text`)은 변경되지 않습니다. **표 행 추가/삭제 등 chunk 경계가 바뀌는 수정**은 [문서 전체 수정] 으로 진행해 주세요."

### 3.3 `files_chunk_edit.html` (신규)

- 폼 필드: `content` (textarea, 초기값 = 현재 `chunk.content`).
- 상단 메타: 문서명, chunk_index, 현재 글자 수(가능하면 토큰 수).
- **경고 박스 (필수 카피)**:
  > "이 화면에서는 **단 하나의 chunk만 재임베딩**됩니다. 이후 **문서 전체 재임베딩**을 실행하면 chunk 단위로 수정한 내용이 **덮어써집니다(사라집니다)**."
- 비용 안내: 하드코딩 달러 추정치 제거. 단순히 "저장 시 **임베딩 API 1회 호출**이 발생합니다." 로 명시. BO에 토큰/비용 추정 유틸이 이미 있다면 동일 스타일 재사용.
- 버튼: `저장 및 재임베딩` / `취소` (→ `bo:chunks`).

### 3.4 `files_review.html` 수정 (READY 문서 전체 재임베딩 경고)

- READY 상태에서 전체 재임베딩 폼이 노출되는 영역 상단에 **항상 표시되는 generic 경고**:
  > "문서 전체 재임베딩은 **모든 chunk 를 새로 생성**합니다. 개별 chunk 편집을 수행한 적이 있다면, 해당 chunk 수정 내용은 **덮어써집니다**."
- 조건부(개별 수정 여부 감지) 표시는 하지 않는다 — §2 결정에 따라 감지 수단이 없음.

### 3.5 사이드바 active 상태 (`bo/templates/bo/base.html`)

- 파일 관련 메뉴 active 조건에 `chunk_edit` URL name 을 포함시킨다. 기존 `files / review / chunks` 와 동일 그룹으로 묶을 것.

### 3.6 GET / POST 동작

| 메서드 | 동작 |
|--------|------|
| GET    | 폼 렌더 |
| POST   | `content` strip 후 비어있으면 폼 에러 재렌더. 토큰 상한 초과면 폼 에러 재렌더(service 호출 안 함). 정상이면 `reembed_chunk` 호출. |

## 4. Chunk 단위 임베딩 재생성 Service 설계

`files/services/pipeline.py`:

```python
def reembed_chunk(chunk: DocumentChunk, new_content: str) -> None:
    """단일 chunk content + embedding 을 원자적으로 갱신.
    실패 시 기존 content/embedding 보존. 예외: PipelineError.
    """
```

알고리즘:
1. `text = new_content.strip()` — 비면 `PipelineError('내용이 비어있습니다.')`.
2. `vector = embed_text(text)` — `EmbeddingError` → `PipelineError` wrap. (atomic 블록 **밖**에서 호출.)
3. `transaction.atomic()` 안에서 `chunk.content = text`, `chunk.embedding = vector`, `chunk.save(update_fields=['content', 'embedding'])`.
4. `document.status`, `document.edited_text`, `document.error_message` 는 건드리지 않는다.

`reembed_document` 와의 차이: 다른 chunk 미접촉, delete+bulk_create 미사용, document 상태/텍스트 미변경.

## 5. Transaction / Rollback 안전 계약

- 임베딩 호출은 atomic 블록 밖. 새 vector 확보 후에만 UPDATE 진입.
- 임베딩 실패 시 DB UPDATE 0건. 호출자에는 `PipelineError`.
- `update_fields=['content', 'embedding']` 명시.
- chunk 단위 실패는 `document.error_message` 에 기록하지 않는다 → Django `messages` 로만 표시.

## 6. `Document.edited_text` ↔ Chunk content 동기화 정책

### 결정: **동기화하지 않는다 (불일치 허용)**. 추가 컬럼/플래그도 도입하지 않는다.

- 사용자가 이후 문서 전체 재임베딩을 수행하면 chunk 단위 수정분은 사라진다 — 의도된 동작.
- 사용자 보호 수단: §3.3 (chunk 편집 화면 경고) + §3.4 (READY 전체 재임베딩 화면 generic 경고). 모두 **항상 표시**.

## 7. 권한 / HTTP Method / CSRF / Validation 계약

- **권한**: 기존 BO 파일 view 패턴과 동일 (별도 staff/login 데코레이터 없음). 본 이슈에서 전역 BO 인증 변경 없음.
- **HTTP method**: GET=폼, POST=저장. 구현은 `@require_http_methods(["GET", "POST"])` 데코레이터 사용을 권장. (기타 메서드 405 보장 + 테스트에서 405 단정 가능.) 미사용 시에는 함수 내 분기로 명시하고, 그 경우 405 단정 테스트는 두지 않는다.
- **CSRF**: Django 기본 미들웨어 + 폼 `{% csrf_token %}`.
- **Validation**:
  - strip 후 빈 문자열 → 폼 에러.
  - **토큰 상한**: `MAX_CHUNK_EDIT_TOKENS = 8000` 상수 (BO view 모듈에 위치). 초과 시 `embed_text` 호출 **전에** 거절, 폼 에러로 표시. (text-embedding-3-small 8191 한도 여유분.)
  - chunk-doc 정합성: `pk=chunk_pk, document_id=pk` 단일 조회 (§3.1).
  - 상태 차단: `chunk.document.status != READY` redirect.

## 9. 수동 QA 시나리오

1. **정상 플로우**: 업로드 → READY → `청크 확인` → 두 번째 chunk `수정` → marker 텍스트 추가 후 저장 → success 메시지 → 채팅에서 marker 질의 시 해당 chunk 검색됨.
2. **embedding 실패**: `OPENAI_API_KEY` 무효화 또는 mock → 수정 시도 → 에러 메시지 + 새로고침 시 원문 유지.
3. **chunk 경계 변경 오용**: 큰 표 행 추가 후 저장 → 검색 품질 일관성 저하를 직접 체감, 안내 문구의 유효성 확인.
4. **READY 외 상태 차단**: REVIEWING/FAILED 문서의 chunk edit URL 직접 입력 → redirect + 메시지.
5. **전체 재임베딩 후 chunk 수정분 손실**: chunk 편집 → 문서 전체 수정/확정 → marker 사라짐 확인. READY review 페이지 generic 경고가 노출됐는지 확인.
6. **토큰 상한**: 8000 토큰을 초과하는 입력 붙여넣고 저장 → 폼 에러, 임베딩 호출 없음.
7. **사이드바**: chunk edit 페이지에서 좌측 파일 메뉴가 활성화 상태인지 확인.
